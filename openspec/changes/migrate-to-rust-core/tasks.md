### Phase 2c (judgment-day fixes — two blind judges, iteration 1)

Two independent blind judges (Sonnet + Opus) reviewed phase 2/2b and reproduced real bugs via throwaway test files (scratchpad `judgeA`/`judgeB`). Root architecture decision (orchestrator, final): **patch-based undo is only sound if EVERY document mutation goes through history** — this closes phase 2b's remaining "non-undoable" carve-outs (2.1/2b.2's deviation note) rather than leaving them for later.

- [x] 2c.1 **judgeA repro 1 (`activeLayerId-dangling`)** — folded into `lib/core/ts-core.judgment-day.test.ts`. Root cause: `layer.remove` was non-undoable, so a later `undo()` of an EARLIER stroke force-restored a recorded `activeLayerId` for a layer that removal had already deleted — dangling id, not present among the frame's current layers. Fixed at the root: `layer.add`/`layer.remove`/`layer.meta`/`layer.reorder` are now undoable (structural entries, `ts-core.ts`), AND `applyEntry` never trusts a recorded `activeLayerId` blindly — `resolveActiveLayerId` falls back to the frame's own current id, then its first layer, so it can never dangle regardless of what else changes the layer stack.
- [x] 2c.2 **judgeA repro 2 (`frame-paste-stale-index`)** — folded into `ts-core.judgment-day.test.ts` (two tests: an end-to-end paste+double-undo, and a direct unit test of `applyEntry`). Root cause: `HistoryEntry`'s patch entries stored `frameIndex` (array position at dispatch time); any LATER structural command that reordered `timeline.frames` (originally only `frame.paste`, now any structural op) silently invalidated every earlier entry's index without updating it, so undo mutated whichever frame happened to now sit at the stale position. Fixed: `HistoryEntry`'s patch variant now stores `frameId` (stable), resolved via `frameIndexById` at apply-time (`lib/core/history.ts`, `lib/core/ts-core.ts`).
- [x] 2c.3 **judgeB repro (`persist.judge.test.ts` — "remount within debounce window loses last stroke")** — folded into `services/document-persistence.remount.test.ts` (uses the real `useSpriteEditorStore`, not a fake). Two root causes in `document-persistence.controller.ts`: (1) `stop()` cancelled a pending debounced save instead of flushing it — fixed, `stop()` now flushes before marking itself stopped; (2) a remount unconditionally re-ran `repository.load()` + `importDocument()`, rolling the live core back to the last SAVED (possibly stale) revision — fixed by gating restore on `docStatus === 'ready'` already being true (the zustand store is a page-lifetime singleton, so a remount within the same session sees it still `'ready'` from the prior mount and skips restore entirely). Also fixed: `save()` now awaits/catches repository errors (`console.error` + `onPersistentChange(false)` instead of an unhandled rejection), and a module-scope `sessionRevision` counter keeps autosave revision numbers monotonic across remounts.
- [x] 2c.4 **Architecture decision — every document mutation is undoable.** `lib/core/commands.ts`/`ts-core.ts`: `layer.add/remove/meta/reorder`, `frame.paste`, `selection.commit`, `region.clear` all now push a history entry (previously non-undoable, see 2.1/2b.2's deviation note — this closes it). `layer.setActive`/`frame.select` and the new `timeline.setFps`/`timeline.toggleLoop`/`timeline.setFrameSelection`/`timeline.togglePlayback` stay non-undoable (view/playback state, not document edits). Redo-stack clearing on any new entry falls out for free — every undoable command already routes through `pushEntry`, which truncates the redo branch on push. Deviation (documented, time-boxed): design's "prefer small structural records over whole-document snapshots" is NOT implemented for the newly-undoable layer/frame ops — they reuse the existing whole-timeline `StructuralDocSnapshot` (already correct, already bounded by eviction) instead of bespoke minimal diff records, to keep this pass's blast radius contained. Tracked as a follow-up, not re-opened here.
- [x] 2c.5 **Undo/redo never leaves a dangling view state.** `applyEntry` (`ts-core.ts`): structural entries restore `frames`/`currentFrameIndex`/`selectedFrameIndices` from the snapshot but DELIBERATELY KEEP the current `fps`/`loop`/`isPlaying` instead of reverting them (judgeB test G, "structural undo restores stale isPlaying/fps" — folded into `ts-core.judgment-day.test.ts`). `doc.replace`'s `fps`/`frameDurationMs` inconsistency fixed: `fps` is now derived from `cmd.frameDurationMs` instead of always resetting to the global default.
- [x] 2c.6 **Stroke lifecycle robustness.** `stroke.begin` while a stroke is already open first commits it (`endOpenStroke`, reused by `stroke.end`); `frame.select`/`undo`/`redo` (core) and tool switches (`compound.slice.ts`'s `setActiveTool`) all force-end any open stroke first; `useCanvasInteraction.hook.ts`'s `handlePointerUp` now ends the stroke UNCONDITIONALLY before any tool-specific branch, not only in the `pencil`/`eraser` fallthrough. `StrokeState` gained a `frameId` so a stroke is bound to the frame+layer it began on (`ts-core.judgment-day.test.ts` covers the re-open and the mid-stroke `frame.select` cases).
- [x] 2c.7 **Bounds validation + locked-layer enforcement.** `stroke.points` bounds-checks every point against the layer buffer before writing (previously wrote straight into a flat index, silently "wrapping" an out-of-range x into the next row — judgeB test H); `fill` bounds-checks its seed point.
